# Avallon System

Отдельный проект расширений для Owlbear Rodeo. Основа скопирована из Odyssey System и Odyssey Initiative; исходные репозитории не изменены. Текущая версия: **1.1.1**.

## Четыре расширения

| Расширение | Манифест | Назначение |
|---|---|---|
| Avallon System | manifest.json | Персонажи, характеристики, навыки, инвентарь, способности и бой |
| Avallon GM Tools | gm-extension/manifest.json | Мастерские броски, атаки окружения и список персонажей |
| Avallon Combat Log | room-log/manifest.json | Отдельный общий журнал Avallon |
| Avallon Initiative | initiative/manifest.json | Общая инициатива, ручные значения, следующий ход и d20 + Реакция |

Манифесты подготовлены для размещения по адресу https://vvinged1.github.io/Avallon-System/. Репозиторий создан. Адреса установки становятся рабочими после успешной публикации GitHub Pages.

## Изменения 1.1.1

Способности имеют собственный уровень навыка 0–5. Атакующая способность использует его для проверки; другие навыки персонажа не требуются. То же правило действует для атакующих способностей протезов. Ранее созданным способностям без уровня устанавливается 0 — ГМ может задать значение через карандаш.

## Изменения 1.1.0

- Способности находятся в Skills вместе с текущим запасом маны. Типы Utility, Activate bonuses и Attack сохранены. В Attack skill можно выбрать атакующую способность; её урон и точность заменяют оружие, а мана расходуется при атаке, включая промах.
- Съёмных магазинов нет: дальнобойное оружие использует только внутреннюю ёмкость и совместимые боеприпасы. Содержимое старых запасных магазинов возвращается в резерв, заряженное оружие сохраняет патроны.
- Импланты переименованы в протезы с сохранением установленных предметов, бонусов и способностей. JSON прежней версии читается.
- Артефакты надеваются без занятия слота брони. Пассивные свойства и бонусы действуют при надевании. Активные эффекты восстанавливают ману, лечат выбранную часть тела или дают снимаемый бонус; стоимость списывается из индивидуального запаса зарядов. Лечение не чинит броню. Заряды восстанавливает ГМ через редактирование предмета. Запасные копии имеют отдельные заряды. В пуле артефакты сохраняются с полным зарядом; на персонаже текущие заряды сохраняются.
- Карточки характеристик стали компактнее.

## Согласованные правила

- Магия нового персонажа равна 0. Остальные базовые характеристики начинаются с 8, обычная прокачка ограничена 15; временные бонусы могут превышать базовый предел.
- Максимальная мана равна эффективной характеристике Магия. Текущий запас хранится отдельно как потраченная мана. ГМ может изменить текущий запас.
- Способность задаёт стоимость использования с точностью 0,5. Есть Utility, Activate bonuses и Attack. Успешно выполненное использование расходует ману; атака расходует её и при промахе. Отмена, недоступная способность, повторно активный эффект и нехватка маны не расходуют ресурс.
- Атакующая способность выбирается в обычных Attack / No Target Attack; использует собственный уровень 0–5, заданные урон и точность. Обычные патроны при этом не расходуются.
- Способности установленной экипировки также могут иметь стоимость маны. Пассивные бонусы не расходуют ману.
- Части тела и места установки настраиваются как в Odyssey. Можно добавлять несколько рук, ног и других частей. На одной части тела остаётся один комплект брони, импланты сохраняют прежние правила установки. Фиксированного ограничения пятью слотами нет.
- Обычные криты по разнице урона: 30 = 1, 60 = 2, 90 = 3. Правила критического броска 95+ и провала 5 и ниже унаследованы из основы Odyssey.
- Классы брони: лёгкая до 35, средняя до 70, тяжёлая выше 70. Для каталога предметов используются ориентиры торс 10/20/30, остальные части 5/10/20. Обученная средняя и тяжёлая броня сохраняет ограничения парирования, скрытности и движения.
- Категории навыков: боевые, прикладные, выживание, управление, социальные, пассивные, способности и заклинания. Пределы 5, 3 и 1 выбираются по категории.
- Расстояние до цели измеряется прежним инструментом. Автоматические бонусы и штрафы дальности оружия пока отключены: таблица Odyssey не применяется.

Это первая база Avallon, а не автоматическая реализация всего PDF. Полный каталог заклинаний, требований к прокачке и перков, школы/аспекты, ОР/ОВ и специальные правила щитов требуют отдельного наполнения. Способности уже можно создавать вручную без этих дополнительных подсистем.

## Изоляция данных

Основные метаданные: com.avallon.system/data. Внутренний лист: avallon. Журнал, пул предметов, шаблоны, контекстные команды, фоновые оверлеи и browser storage имеют отдельные ключи. Initiative хранит порядок в com.avallon.initiative/metadata и читает эффективную Реакцию Avallon с учётом предметов, эффектов и водителя транспорта.

Avallon не изменяет com.codex.body-hp/data и не переносит автоматически персонажей, библиотеки или журнал Odyssey. Шаблоны сохраняют способности; применение шаблона начинает персонажа с полным запасом маны.

Основная работа остаётся на метаданных токена/сцены и локальном резервном сохранении библиотек. Supabase и внешний backend не подключаются. Унаследованный опциональный bridge отключён по умолчанию.

## Сборка и проверка

Требуется Node.js 20+ и npm.

    npm ci
    npm test
    npm run build
    npm run test:ui
    npm run package:site

Для браузерных проверок нужен Chromium Playwright: npx playwright install chromium, либо переменная PLAYWRIGHT_BROWSERS_PATH с расположением установленного браузера.

Сборка создаёт пять JS bundle: основной интерфейс, фон, GM Tools, журнал и Initiative. Все статические файлы уже собраны и включены в репозиторий. Команда package:site готовит отдельную папку .site без node_modules, тестовых данных и файлов Git. Инструкции и проверенная конфигурация лежат в .github/workflows/pages.yml.

Проверки охватывают границы критов, ману и дробные стоимости, категории, дополнительные конечности, изоляцию метаданных, магазинный боезапас, библиотеку предметов, два одновременных окна ГМ, все четыре интерфейса и формы на ширинах 360/480/620/1000 px.

## Публикация

1. Предоставить подключённой GitHub-интеграции запись в VVinged1/Avallon-System.
2. Загрузить ветку feature/avallon-system. В Settings → Pages выбрать Source: GitHub Actions. Workflow собирает и публикует статическую сборку проекта; при включении Pages после загрузки его можно запустить через Actions → Publish Avallon System → Run workflow.
3. Только после успешного deployment установить четыре HTTPS-манифеста из таблицы.
